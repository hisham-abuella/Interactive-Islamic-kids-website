## Verdict: NOT READY TO COMMIT

The site changes are mechanically sound. All five verifiers pass, the Bismillah check catches a
re-added ۝, the 108 page loads show no new console errors, and narration is aligned for all 37
changed units. Four things block the commit:

1. **The scholar's own confirmation review is not cleared.**
   `claudeteam/reviews/site-fixes-scholar-confirm-2026-11-04.md` (22:08, written after the mp3s
   were made around 19:00) leaves two MUSTs and one SHOULD open:
   - **C1, MUST.** The Arabic TTS still recites Quranic wording. This is the rule that no
     synthesised voice reads Quranic Arabic. The affected AR scripts:
     - Ibrahim slide 6: «قلنا يا نار كوني برداً وسلاماً على إبراهيم»
     - Musa slide 5: «إني أنا ربك»
     - Musa slide 8: «فقولا له قولاً ليناً»
     - Yusuf slide 8: «...يغفر الله لكم، وهو أرحم الراحمين»
     - Yusuf slide 10: the dua
     These are in `UI/voice-scripts.js` and `UI/scripts/voice-scripts-data.json`, and the
     matching mp3s.
   - **C3, MUST.** The Kursi chair emoji 🪑 is still on three pages: `UI/ayat-al-kursi.html:50`,
     `UI/quran.html:428`, `UI/index.html:117`.
   - **C2, SHOULD.** In Musa slide 1, "basket" sits inside what Allah inspired
     (`UI/story-prophet-musa.html:88`). The fix also needs a voice-scripts edit and a re-take of
     `audio/prophet-musa/{en,ar}/slide-1.mp3`.
2. **The print build fails.** `tools/build-volumes.sh --draft vol-surahs-1` exits 1 because
   `verify-print-scripture.py` fails on three stories:
   - Ibrahim and Musa: the `print/books/story-*.html` files are stale (built 17:13, before the
     story ayah blocks were added). Re-extracting them fixes both (checked in a scratch copy).
   - **Yusuf fails even after a fresh extract** ("2 spans vs 3"). The verifier counts 12:101
     twice: once from `data-ayah="12:101"`, and again as the dua, which is the same element.
     The extractor emits it once. This is a bug in the verifier (or the extractor) and must be
     fixed before any volume containing Yusuf can pass.
   - The draft's "images under 300ppi" failures are expected for `--draft` (960px web plates).
3. **The new story-ayah CSS has no effect on the slide-mode stories.** In Ibrahim and Musa,
   `.story-slide .scene-text p {font-size:1rem}` (specificity 0,2,1) beats
   `.scene-text .story-ayah {font-size:1.7rem}` (0,2,0). The ayah for 21:69, 20:12 and 20:44
   renders at 16px (15.2px at 390), the same size as the prose around it. In EN mode its font
   is Nunito, falling back to a system Arabic face. Only Yusuf (classic-scroll) gets 1.7rem;
   the CSS comment names only Yusuf, so it looks like only Yusuf was tested. Severity: should
   fix. Nothing is broken, but the Quran is not set apart from the story text.
4. **The lead's numbers do not reproduce** (details below): 37 mp3s were replaced, not 27, and
   12 plates changed, not 11. The work looks consistent; the numbers in the hand-off are wrong
   and should be corrected before they go in a commit message.

## Non-blocking observations
- The cache-busting query strings were not bumped after the CSS edits: pages still load
  `stories.css?v=20261001` and `surah.css?v=20261008`. A returning visitor can get the old CSS,
  with no `.full-bismillah` rule, until their cache expires. Then the Bismillah runs into ayah 1.
- At 390px the story slide text column is about 119px wide. The same is true on HEAD, so this
  predates the change, but it is cramped for a child.
- In the complete-surah block, a ۝ can wrap to the start of the next line (seen in Bayyinah,
  after البينة). This predates the change: the space before ۝ allows a line break there.
